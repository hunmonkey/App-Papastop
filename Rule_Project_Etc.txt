============================================================
프로젝트 아키텍처 및 폴더 구조 가이드
============================================================

이 문서는 AI 에이전트와 새로운 개발자가 프로젝트의 전체적인 구조를 
빠르게 파악하고 일관성 있게 코드를 작성하도록 돕는 핵심 길잡이입니다.
새로운 요구사항을 구현하기 전, 반드시 이 문서를 참조하여 알맞은 폴더와 방식을 선택하세요.

0. 공통 작업 지침
------------------------------------------------------------
- `AGENTS.md`와 `CLAUDE.md`는 이 프로젝트뿐 아니라 모든 작업의 기본 지침입니다.
- 작업 행동, 호칭, 배포, 보안, 터미널 안전 규칙은 두 문서를 우선 적용합니다.
- 프로젝트 루트의 `AGENTS.md` / `CLAUDE.md` 사본은 전역 기준 파일과 같은 내용으로 유지합니다.
- 개발, 수정, 테스트 작업은 원칙적으로 `dev` 브랜치에서 진행합니다.
- 사용자가 GitHub 최신화/연동을 요청하면 `main`과 `dev` 브랜치를 모두 최신 커밋으로 맞춰 푸시합니다.

1. 작업 기록 문서
------------------------------------------------------------
- `Rule_Project_Etc.txt`: 프로젝트 구조, 핵심 기술 스택, 작업할 때 먼저 봐야 할 기준을 적어두는 안내 문서입니다.
- `Rule_ToDo.txt`: 현재 진행할 작업 계획과 대기/진행 중인 작업을 적어두는 문서입니다.
  - 새 작업을 시작하기 전에 작업 목표, 수정 위치, 검증 방법을 짧게 기록합니다.
  - 작업 상태는 `[대기]`, `[진행]`, `[완료]`, `[실패]` 중 하나로 적습니다.
  - 동시에 `[진행]` 상태는 하나만 두어, 여러 작업이 섞여 길을 잃지 않게 합니다.
- `Rule_Todo_Done.txt`: `Rule_ToDo.txt`에서 끝난 작업을 옮겨 보관하는 완료 기록 문서입니다.
  - `Rule_ToDo.txt`의 작업 묶음이 모두 `[완료]` 또는 `[실패]`가 되면, 해당 묶음을 `Rule_Todo_Done.txt` 맨 아래로 옮깁니다.
  - 기존 완료 기록은 지우지 않고, 구분선(`------------------------------------------------------------`) 아래에 이어서 기록합니다.
- 문서 갱신 시 파일명과 함수명은 정확히 적고, 확인하지 못한 내용은 `미검증`이라고 표시합니다.
- 완료 기록 파일명은 현재 저장소 기준 `Rule_Todo_Done.txt`입니다.


2. 배포 빌드 규정
------------------------------------------------------------
- 배포 빌드(EXE 재제작)는 황재훈 님의 지시가 있으면 AI가 직접 실행한다.
  (과거의 "빌드는 사용자가 직접 실행" 관례는 폐지되었다. 지시가 있을 때만 AI가 실행한다.)
- 일반 배포본: `build_package.ps1` (모델 캐시까지 동봉, 용량 큼).
- 최소 배포본: `build_package_min.ps1` (모델 미동봉, 첫 실행 시 자동 다운로드).
- 권장 실행: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build_package.ps1 -SkipInstall`
- 빌드 전 `python -m py_compile papastop.py`로 문법을 확인한다.
- PyInstaller가 onnxruntime/torch tensorboard/llama_cpp/CUDA DLL 경고를 내도 즉시 실패로 보지 말고,
  마지막 `Package created:` 문구와 실제 EXE/데이터 폴더를 확인한다.


3. "1사이클 반영" 정의
------------------------------------------------------------
- 황재훈 님이 "1사이클 반영해"라고 하면 아래를 순서대로 진행·완료한다.
  1) Rule_todo*.txt 갱신 (완료된 작업 묶음을 Rule_Todo_Done.txt로 이관하고 진행 계획을 정리한다)
  2) 배포버전 재빌드가 필요하면 재빌드한다 (2. 배포 빌드 규정을 따른다)
  3) GitHub 최신버전 적용 (main·dev 브랜치를 모두 최신 커밋으로 맞춰 push한다)
  4) dev 브랜치로 복귀한다
