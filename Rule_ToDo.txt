============================================================
AI 작업 인수인계용 진행 기록 / To-Do
============================================================

이 파일은 사람(황재훈 님)과 AI, 그리고 AI들 사이의 "공용 메모장 + 투두리스트"입니다.
사전 정보가 전혀 없는 AI라도 이 파일을 읽고 어떤 작업을 이어서 해야 하는지 파악해 일관되게 이어갈 수 있어야 합니다.
짧고 정확하게 기록한다.


------------------------------------------------------------
■ 이 파일의 사용 규칙 (AI는 반드시 지킬 것)
------------------------------------------------------------
1. 작업을 시작하기 전에 작업 계획, 단계, 내용에 대해 기록한다.
2. 기록을 할 때 현재상태, 작업 제목, 날짜 및 시각 (YYYY-MM-DD HH:MM:SS), 어디, 무엇/어떻게, 검증을 기록한다. (상태는 대기, 진행, 완료, 실패 4가지 중 하나를 사용한다.)

(예시)

[완료] 2-1. 데이터 폴더 방식 전환  (2026-05-31 14:30:31)
  어디: papastop.py
  무엇/어떻게:
   · APP_CACHE_DIR 폴더명을 ".papastop_cache" → ".papastop_data" 로 변경.
   · prepare_cuda_library_path(): EXE에서 _MEIPASS 번들 대신 외부 APP_CACHE_DIR/"nvidia"에서 CUDA를 찾도록 변경.
   · nllb_model_dir(): EXE 번들(_MEIPASS) 분기를 제거하고 항상 외부 폴더(NLLB_MODEL_DIR) 사용.
   · Whisper는 원래부터 외부 HF 캐시(.papastop_data/huggingface)를 쓰므로 변경 없음.
   · 개발 폴더 .papastop_cache → .papastop_data 로 이름 변경(데이터 보존).
  검증: _MEIPASS 잔존 참조 없음 확인. is_frozen_app은 다른 곳에서 계속 사용되어 유지.

3. 순서대로 작업을 진행하며 [대기] 상태의 작업을 [진행]으로 변경한 후 작업 진행한다. (진행은 항상 하나만 둔다.)
4. [진행] 상태의 작업을 완료한 이후 상태를 [완료]로 변경하며 다음 순서의 [대기] 작업을 [작업] 으로 변경 한 후 이어서 작업 진행한다.
5. 모든 작업의 상태가 [완료] 또는 [실패]로 변경되면 '작업 진행 계획'에 있는 내용 전체를 루트 폴더의 'Rule_Todo_Done.txt 파일로 이동시킨다. (완료와 실패가 섞여있어도 이동)
6. '작업 진행 계획'은 다음 질문에 대한 작업을 위하여 깨끗이 비워둔다.
6. 파일명·함수명은 정확히 적는다. (줄 번호는 코드가 바뀌면 어긋나므로 함수명 위주로 쓴다.)
7. 추정이 아니라 확인된 사실을 적는다. 확인 못 한 것은 "미검증"이라고 표시한다.


------------------------------------------------------------
■ 프로젝트 한 줄 요약
------------------------------------------------------------
PapaStop: 영상·음성을 자막(SRT)으로 만들고 번역하는 Windows 데스크톱 앱.
 - 단일 파일 papastop.py (tkinter GUI)
 - 음성→자막(STT): faster-whisper (CTranslate2, GPU 가속)
 - 번역: NLLB-200-1.3B (ctranslate2) / Argos
 - 빌드/배포: PyInstaller (build_package.ps1)
 - 폴더 구조·기술 스택 상세는 Rule_Project_Etc.txt 참조.

   · papastop.py는 변경 없음: 모델 부재 시 자동 다운로드가 이미 구현됨
     (Whisper download_root, NLLB는 CT2 없으면 transformers pipeline 폴백).
  검증: build_package_min.ps1 PowerShell 파서 통과 확인. 실제 EXE 빌드는 미실행(수십 분 소요, 황재훈 님이 직접 실행).

[완료] 2. 모델 다운로드 진행률·예상시간 GUI 실시간 표시  (2026-06-03 18:40:00)
  어디: papastop.py
  무엇/어떻게:
   · faster-whisper·transformers·llama_cpp는 모두 huggingface_hub로 모델을 내려받으므로,
     huggingface_hub의 tqdm(클래스: huggingface_hub.utils.tqdm)의 __init__/update/close를 한 번만 감싸는 후크 추가.
   · 신규 모듈 함수: set_download_progress_callback, _report_tqdm_progress, _has_real_std_stream,
     install_hf_download_hook (hf_file_cached 아래에 배치). 바이트 단위(unit='B') 다운로드만 진행률로 처리.
   · App.__init__: event_queue 생성 직후 install_hf_download_hook() 호출 +
     set_download_progress_callback(lambda d: self._emit("download_progress", d)) 연결.
   · _process_events: "download_progress" 분기 추가 → _handle_download_progress(payload).
   · _handle_download_progress(신규): 공통 진행 영역(status_var/progress/eta_var)에
     "모델 다운로드 중: {파일} {%} (받은용량/전체용량)" + "예상 시간: 약 N 남음 · 완료 예상 HH:MM" 표시.
   · 0.15초 throttle로 이벤트 큐 폭주 방지. enable_progress_bars()로 진행바 강제 활성화(꺼져 있으면 n 미갱신).
   · windowed(EXE) 환경에서 표준 스트림(sys.stderr/stdout)이 없을 때 tqdm 출력을 io.StringIO 더미로 돌려 예외 방지.
  검증: py_compile 통과. 후크 단위 테스트로 바이트 tqdm은 50/100% 이벤트 발생, 개수(unit='it') tqdm은 무시 확인.
        sys.stderr/stdout=None(windowed 흉내)에서도 예외 없이 진행률 수신 확인.
