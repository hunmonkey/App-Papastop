PapaStop UI / UX 공식 규정
정리일: 2026-06-01

목적
================================================================================
이 문서는 PapaStop의 모든 화면을 같은 기준으로 정리하기 위한 공식 UI / UX 규정이다.
PapaStop은 웹사이트가 아니라 Windows 데스크톱용 자막 제작 도구다.
따라서 규칙의 중심은 "예쁘게 꾸민 화면"이 아니라 "황재훈 님이 파일을 고르고, 작업을 시작하고,
진행 상황과 결과를 바로 확인할 수 있는 화면"이다.

디자인 목표:
- 밝고 선명한 데스크톱 작업 도구처럼 보인다.
- 다음에 눌러야 할 버튼이 바로 보인다.
- 파일 경로, 모델 선택, 진행률, 로그가 서로 밀리지 않고 읽힌다.
- 화려한 장식보다 작업 순서와 상태 표시가 먼저다.


0. 적용 범위와 우선순위
================================================================================

0-1. 적용 범위
--------------------------------------------------------------------------------
- PapaStop 프로그램 전체에 적용한다.
- 대상 파일은 기본적으로 `papastop.py` 하나다.
- `customtkinter` 위젯을 우선 사용하고, 꼭 필요한 경우에만 기본 `tkinter` 위젯을 섞는다.

0-2. 문서 우선순위
--------------------------------------------------------------------------------
UI / UX 판단 순서는 아래와 같다.

1. AGENTS.md / CLAUDE.md의 전역 작업 지침
2. Rule_Project_Etc.txt의 프로젝트 구조 설명
3. Rule_UIUX.txt
4. 기존 `papastop.py`의 검증된 동작

작업 행동, 호칭, 배포, 보안, 터미널 안전 규칙은 AGENTS.md / CLAUDE.md를 우선한다.
이 문서와 기존 코드가 다르면, 새 UI 작업부터 이 문서를 기준으로 맞춘다.

0-3. 구현 위치
--------------------------------------------------------------------------------
PapaStop은 CSS 파일이 없는 단일 Python GUI 앱이다. 공통 UI 규칙의 주인은 아래 위치로 고정한다.

- 색상 토큰: `papastop.py` 상단의 `UI_BG`, `UI_SURFACE`, `UI_BORDER`, `UI_TEXT`, `UI_ACCENT` 계열
- customtkinter 전역 테마: `PapaStopApp._apply_theme()`
- 카드 공통 구조: `PapaStopApp._make_card()`
- 선택창 테두리 래퍼: `PapaStopApp._make_option_menu()` (CTkOptionMenu에 1px 테두리를 입힌다)
- 버튼/입력칸/선택창 공통 옵션: `_ghost_btn`, `_danger_btn`, `_entry_kw`, `_option_kw`, `_primary_btn_kw`, `_stop_btn_kw`, `_open_btn_kw`
- 전체 화면 배치(왼쪽 사이드바 + 오른쪽 영역)와 탭 전환: `PapaStopApp._build_ui()`, `PapaStopApp._show_tab()`
- 실시간 자막 오버레이: `LiveSubtitleOverlay`

금지:
- 같은 색상값을 함수 안에 여기저기 직접 쓰는 방식
- 버튼마다 높이, 둥근 정도, 글자색을 따로 지정하는 방식
- 화면 아래쪽에 임시 보정 코드를 계속 덧붙이는 방식
- 기능 변경 없이 장식용 카드, 장식용 문구, 장식용 색을 늘리는 방식


1. PapaStop 화면의 핵심 구조
================================================================================

1-1. 첫 화면과 탭 순서
--------------------------------------------------------------------------------
PapaStop의 기본 작업은 자막 제작이다. 탭은 왼쪽 세로 사이드바에 위에서 아래로 고정한다.

1. 파일 자막
2. 실시간 자막
3. 화면 녹화
4. 시스템 사양

첫 탭은 항상 `파일 자막`이며 앱을 켜면 이 탭이 먼저 보인다.
`시스템 사양`은 보조 확인 화면이므로 맨 아래(맨 뒤)에 둔다.

1-2. 화면의 큰 덩어리
--------------------------------------------------------------------------------
앱 화면은 왼쪽 세로 사이드바와 오른쪽 작업 영역으로 나눈다.

- 왼쪽: 탭을 고르는 세로 사이드바 (창 전체 높이)
- 오른쪽 위: 현재 선택한 작업 탭의 내용
- 오른쪽 아래: 진행 상황과 작업 기록

오른쪽 아래 진행 영역은 항상 보이게 둔다.
사용자는 작업 중에 탭을 보다가도 진행률, 예상 시간, 로그를 바로 확인할 수 있어야 한다.
내용이 적은 탭은 오른쪽 위 영역 아래에 여백이 생길 수 있으며, 이는 자연스러운 상태로 둔다.

1-3. 작업 순서
--------------------------------------------------------------------------------
각 탭은 가능하면 아래 흐름을 따른다.

1. 무엇을 처리할지 고른다.
2. 어디에 저장할지 고른다.
3. 필요한 모델이나 옵션을 고른다.
4. 시작 버튼을 누른다.
5. 진행률과 로그를 확인한다.
6. 결과 열기 버튼으로 결과를 확인한다.

이 순서가 깨지면 사용자는 길을 잃는다.
새 기능을 넣을 때도 이 흐름 안에 넣는다.

1-4. 화면 밀도
--------------------------------------------------------------------------------
PapaStop은 오래 읽는 문서가 아니라 반복해서 쓰는 도구다.
넓은 홍보용 여백보다, 입력칸과 버튼이 차분히 정렬된 밀도 있는 화면을 우선한다.

기준:
- 기본 창 크기: 980~1120px 너비를 기준으로 보기 좋게 만든다.
- 최소 창 크기: 900x620에서도 버튼과 글자가 겹치지 않아야 한다.
- 파일 목록과 로그는 자기 영역 안에서 스크롤한다.
- 앱 전체가 과도하게 세로로 길어져 핵심 버튼이 화면 밖으로 밀리면 실패로 본다.


2. 색상 규정
================================================================================

2-1. 기본 팔레트
--------------------------------------------------------------------------------
PapaStop은 밝은 라이트 테마를 기본으로 한다.
색상은 아래 역할 안에서만 사용한다.

아래 값은 실제 `papastop.py` 상단 토큰과 1:1로 같다. 문서와 코드가 어긋나지 않게 한쪽을 바꾸면 다른 쪽도 같이 바꾼다.

역할                   권장값      토큰                사용 위치
--------------------------------------------------------------------------------
앱 배경                #e6eaf2     UI_BG               창 전체 배경
카드/입력 표면         #ffffff     UI_SURFACE          카드, 입력칸, 목록, 로그
살짝 강조 배경         #eef2ff     UI_SURFACE_HOVER    보조 버튼 hover, 탭 hover, 드롭다운 목록 hover
기본 테두리            #d6dbe6     UI_BORDER           옅은 구역 경계, 진행률 바 바탕
강한 테두리            #9aa6ba     UI_BORDER_STRONG    입력칸, 목록, 로그 경계
카드 테두리            #b0bac9     UI_CARD_BORDER      카드 구분선
본문 글자              #0f172a     UI_TEXT             주요 문구
보조 글자              #64748b     UI_TEXT_MUTED       설명, 상태 보조 정보
핵심 액션(옅은 인디고)  #6366f1     UI_ACCENT           시작 버튼, 진행률, 선택 강조, 드롭다운 화살표 칸
핵심 액션 hover        #5457e6     UI_ACCENT_HOVER     핵심 버튼 hover
핵심 액션 active       #4548c9     UI_ACCENT_ACTIVE    핵심 버튼 눌림
중지/위험              #dc2626     -                   중지, 삭제, 실패
중지/위험 hover        #b91c1c     -                   위험 버튼 hover

핵심 액션은 "눈에 자극적이지 않은 옅은 인디고"로 한다. 진한 인디고(#4f46e5)나 형광 파랑은 쓰지 않는다.
색은 소금처럼 조금만 쓴다. 많이 넣을수록 화면이 맛을 잃는다.

2-2. 색상 사용 원칙
--------------------------------------------------------------------------------
- 옅은 인디고 강조색(`UI_ACCENT`)은 "진행할 수 있는 주요 행동"에만 사용한다.
- 빨간색은 "중지", "삭제", "실패"처럼 멈추거나 위험한 상황에만 사용한다.
- 회색은 배경과 테두리, 보조 설명에만 사용한다.
- 초록색은 완료 상태를 꼭 구분해야 할 때만 제한적으로 사용한다.
- 진하고 자극적인 보라/형광색, 그라디언트, 네온 효과는 기본 UI에 사용하지 않는다.
- 강조색은 옅은 인디고 한 가지로만 절제해서 쓴다. 큰 면을 통째로 강조색으로 칠하지 않는다.

금지 예:
- 한 화면에서 파랑, 보라, 청록, 초록을 모두 강조색처럼 쓰기
- 버튼마다 다른 색을 부여하기
- 드롭다운/선택창 전체를 진한 강조색 블록으로 칠하기
- 로그와 상태 문구를 너무 흐린 회색으로 표시하기
- 카드 배경을 여러 색으로 나눠 장식하기

2-3. 실시간 자막 오버레이 색상
--------------------------------------------------------------------------------
실시간 자막 오버레이는 일반 앱 화면과 목적이 다르다.
영상 위에 올라가므로 어두운 배경과 밝은 글자를 사용한다.

- 배경: `OVERLAY_BG` 계열의 짙은 남색 또는 검정에 가까운 색
- 글자: `OVERLAY_FG` 계열의 거의 흰색
- 테두리: 과하지 않은 파란색 강조
- 투명도: 글자가 읽히는 것이 최우선이다. 멋보다 가독성이 먼저다.


3. 글자와 문구 규정
================================================================================

3-1. 글꼴
--------------------------------------------------------------------------------
Windows에서 한글이 깨지지 않는 글꼴을 우선한다.

우선순위:
1. Segoe UI Variable Text
2. Segoe UI Variable
3. Segoe UI
4. Malgun Gothic

customtkinter 기본 글꼴이 한글에 약하면 `resolve_ui_font_family()`를 통해 한글 지원 글꼴로 고정한다.

3-2. 글자 크기
--------------------------------------------------------------------------------
- 기본 본문: 13px
- 카드 제목: 14px, 굵게
- 실시간 자막 미리보기: 15px
- 로그: 12~13px
- 버튼: 13px

작은 화면에서 글자가 잘린다고 글자를 계속 줄이지 않는다.
먼저 줄바꿈, 입력칸 폭, 버튼 문구를 정리한다.

3-3. 문구 톤
--------------------------------------------------------------------------------
문구는 짧고 직접적으로 쓴다.
사용자가 해야 할 행동을 말한다.

표준 문구:
- 파일 자막 시작: "자막 만들기 시작"
- 실시간 자막 시작: "시작"
- 화면 녹화 시작: "녹화 시작"
- 작업 멈춤: "중지"
- 결과 확인: "결과 열기"
- 파일 선택: "선택"
- 폴더 선택: "폴더 선택"
- 모델 준비: "모델 다운로드" 또는 "모델 준비"

금지:
- 같은 뜻으로 "추가", "등록", "삽입"을 섞어 쓰기
- 사용자가 이해하기 어려운 엔진 이름만 버튼에 쓰기
- 긴 설명문을 화면 안에 계속 노출하기


4. 버튼 규정
================================================================================

4-1. 버튼 종류
--------------------------------------------------------------------------------
버튼은 아래 세 종류로 제한한다.

1. 주요 버튼
   - 예: 자막 만들기 시작, 시작, 녹화 시작
   - 색상: 파란색 배경
   - 높이: 34px (입력칸과 같은 높이로 맞춰 균형을 잡는다)
   - 너비: 140px 기준

2. 중지/위험 버튼
   - 예: 중지, 선택 삭제, 전체 비우기
   - 색상: 빨간색 또는 빨간색 테두리
   - 높이: 주요 버튼과 같은 줄이면 34px, 목록 보조 버튼이면 32px
   - 작업 중이 아닐 때는 비활성화한다.

3. 보조 버튼
   - 예: 선택, 목록에 추가, 폴더 선택, 결과 열기, 모델 다운로드
   - 색상: 흰색 또는 투명 배경 + 파란 글자/테두리
   - 높이: 34px, 파일 목록 옆 버튼은 32px

4-2. 버튼 배치
--------------------------------------------------------------------------------
- 시작 버튼은 왼쪽에 둔다.
- 중지 버튼은 시작 버튼 바로 오른쪽에 둔다.
- 결과 열기 버튼은 같은 줄 오른쪽 끝에 둔다.
- 파일 목록 조작 버튼은 목록 오른쪽에 세로로 쌓는다.
- 같은 줄의 버튼 높이는 반드시 같아야 한다.

실패로 보는 배치:
- 시작 버튼보다 선택/다운로드 버튼이 더 강하게 보이는 경우
- 중지 버튼이 파란색인 경우
- 한 줄 안에서 버튼 높이가 제각각인 경우
- 버튼이 입력칸보다 과하게 커서 화면 균형을 깨는 경우


5. 입력칸, 선택창, 목록
================================================================================

5-1. 입력 행
--------------------------------------------------------------------------------
파일 경로와 저장 경로 행은 가장 자주 쓰는 영역이다.

규칙:
- 왼쪽 라벨은 같은 폭으로 맞춘다.
- 가운데 입력칸은 남는 폭을 모두 사용한다.
- 오른쪽 버튼은 고정 폭으로 둔다.
- 입력칸 높이는 34px로 맞춘다.
- 긴 경로가 들어와도 버튼이 화면 밖으로 밀리면 안 된다.

5-2. 선택창
--------------------------------------------------------------------------------
모델, 원본 언어, 초당 화면 수 같은 선택창은 `CTkOptionMenu`를 사용한다.

규칙:
- 높이 34px
- 둥근 정도는 입력칸과 같게
- `CTkOptionMenu`는 테두리 인자를 지원하지 않으므로, 입력칸과 같은 1px 테두리가 보이도록
  `_make_option_menu()`로 강한 테두리(`UI_BORDER_STRONG`) 띠 프레임에 감싸 만든다.
- 선택창은 통째로 강조색을 칠하지 않는다. 흰색 배경 + 본문 글자색으로 입력칸처럼 보이게 하고,
  오른쪽 화살표 칸에만 옅은 인디고(`UI_ACCENT`)를 쓴다. 펼친 목록도 흰 배경 + 본문 글자색으로 둔다.
- 너무 긴 선택지는 줄여서 보이고, 자세한 설명은 로그나 안내 문구에서 보충한다.
- 같은 종류의 선택창은 같은 폭을 사용한다.

5-3. 파일 목록
--------------------------------------------------------------------------------
파일 목록은 `파일 자막` 탭의 핵심 영역이다.

규칙:
- 목록은 카드 안에서 충분한 높이를 가진다.
- 목록 자체가 스크롤되고, 앱 전체가 불필요하게 길어지지 않게 한다.
- 선택된 파일은 파란색으로 확실히 표시한다.
- 목록 조작 버튼은 오른쪽 세로 버튼 묶음으로 통일한다.
- 빈 목록일 때도 영역 크기는 유지한다.


6. 카드와 여백
================================================================================

6-1. 카드 사용
--------------------------------------------------------------------------------
카드는 서로 다른 작업 덩어리를 구분할 때만 쓴다.

허용:
- 현재 PC 사양
- 작업할 파일 목록
- 실시간 소리 입력
- 녹화 설정
- 진행 상황과 작업 기록

금지:
- 카드 안에 또 카드를 넣는 구조
- 설명 한 줄만 넣기 위한 카드
- 장식용 그림자와 색 배경을 가진 카드

6-2. 둥근 정도와 테두리
--------------------------------------------------------------------------------
- 카드: radius 6px
- 입력칸, 선택창, 일반 버튼: radius 4px
- 진행률 바: radius 3px
- 테두리 두께: 1px

너무 둥글면 둔해 보이므로 모서리는 절제해서 둥글린다.
화면마다 radius를 다르게 주지 않는다.
둥근 정도는 가구의 모서리처럼, 집 안에서 한 스타일로 맞춘다.

6-3. 여백
--------------------------------------------------------------------------------
- 창 바깥 여백: 14px 기준
- 카드 안쪽 좌우 여백: 14px 기준
- 입력 행 세로 간격: 6px 기준
- 관련 없는 구역 사이 간격: 8~14px 기준

여백은 숨 쉬는 공간이다.
하지만 PapaStop은 작업 도구이므로 홍보 페이지처럼 크게 비우지 않는다.


7. 진행 상황과 로그
================================================================================

7-1. 진행 영역
--------------------------------------------------------------------------------
아래쪽 `진행 상황과 작업 기록` 영역은 모든 작업에서 공통으로 쓴다.

반드시 표시:
- 현재 상태
- 예상 시간
- 진행률 바
- 작업 로그

진행률 바는 0%일 때도 보여야 한다.
작업 중에는 사용자가 "멈춘 건지, 일하는 중인지" 바로 알 수 있어야 한다.

7-2. 로그
--------------------------------------------------------------------------------
로그는 사용자가 문제 상황을 설명할 때 가장 중요한 단서다.

규칙:
- 로그는 아래쪽 공통 영역 안에서 스크롤한다.
- 한 줄에 너무 많은 정보를 몰아넣지 않는다.
- 오류는 "무엇이 문제인지"와 "다음에 무엇을 하면 되는지"를 같이 보여준다.
- 내부 개발자용 긴 오류는 필요한 경우에만 뒤쪽에 붙인다.

예:
- 좋음: "ffmpeg를 찾지 못했습니다. 설치 후 다시 실행해 주세요."
- 나쁨: "RuntimeError: command failed"


8. 상태와 비활성화
================================================================================

8-1. 작업 중 상태
--------------------------------------------------------------------------------
파일 자막, 실시간 자막, 화면 녹화 중에는 충돌이 생길 수 있는 버튼을 비활성화한다.

예:
- 작업 중에는 모델 선택 변경을 막는다.
- 작업 중에는 시작 버튼을 비활성화한다.
- 작업 중에는 중지 버튼만 활성화한다.
- 모델 다운로드 중에는 다른 무거운 작업 시작을 막는다.

비유하자면, 믹서기가 돌고 있을 때 뚜껑을 열지 못하게 하는 것과 같다.

8-2. 빈 상태
--------------------------------------------------------------------------------
빈 화면은 짧고 친절하게 안내한다.

예:
- "0개 파일"
- "대기 중"
- "실시간 한국어 자막이 여기에 표시됩니다."
- "아직 열 수 있는 결과 파일이 없습니다."

빈 상태에 긴 설명을 많이 넣지 않는다.


9. 실시간 자막 화면
================================================================================

9-1. 실시간 자막 탭
--------------------------------------------------------------------------------
실시간 자막 탭은 "입력 선택 -> 시작 -> 미리보기 확인" 흐름을 유지한다.

규칙:
- 입력 방식은 라디오 버튼으로 고른다.
- URL 입력칸은 인터넷 URL 스트림 선택과 가까운 위치에 둔다.
- 자막 창 표시, SRT 저장 여부는 체크박스로 둔다.
- 미리보기는 충분한 글자 크기로, 줄바꿈이 자연스럽게 되게 한다.

9-2. 자막 오버레이
--------------------------------------------------------------------------------
오버레이는 영상 위에서 읽히는 것이 목적이다.

규칙:
- 항상 위에 뜨는 창임을 사용자가 예측할 수 있어야 한다.
- 드래그해서 옮길 수 있어야 한다.
- 글자는 크게, 배경은 충분히 어둡게 둔다.
- 화려한 반투명 효과보다 글자 선명도를 우선한다.


10. 화면 녹화 화면
================================================================================

화면 녹화 탭은 옵션이 적어야 한다.
사용자가 가장 많이 확인해야 하는 것은 저장 위치, 초당 화면 수, 소리 녹음 여부다.

규칙:
- 저장할 MKV 경로는 첫 줄에 둔다.
- 초당 화면 수는 24 / 30 / 60 중 선택한다.
- PC 스피커 소리 녹음은 체크박스로 둔다.
- 녹화 시작과 중지는 파일 자막, 실시간 자막과 같은 버튼 규칙을 따른다.


11. 시스템 사양 화면
================================================================================

시스템 사양은 작업 전 확인용 보조 화면이다.

규칙:
- CPU, RAM, VGA를 읽기 쉬운 행으로 보여준다.
- 자원 사용 모드는 너무 전문적으로 보이지 않게 "최대 성능", "균형"처럼 표현한다.
- 새로고침 버튼은 보조 버튼으로 둔다.
- 긴 장치 이름은 줄바꿈을 허용한다.


12. 접근성과 사용성
================================================================================

12-1. 읽기 쉬움
--------------------------------------------------------------------------------
- 본문 글자는 배경과 충분히 대비되어야 한다.
- 보조 글자도 실제로 읽을 수 있어야 한다.
- 버튼 안 글자가 잘리면 버튼 폭이나 문구를 조정한다.
- 한글이 깨지면 UI 실패로 본다.

12-2. 키보드와 포커스
--------------------------------------------------------------------------------
- 입력칸, 버튼, 선택창은 Tab 키로 자연스럽게 이동할 수 있어야 한다.
- 포커스 표시를 이유 없이 없애지 않는다.
- 메시지 박스는 사용자가 확인해야 하는 중요한 상황에만 사용한다.

12-3. 창 크기
--------------------------------------------------------------------------------
확인해야 할 화면 크기:
- 최소 크기: 900x620
- 기본 크기: 1120x760 안팎
- 큰 화면: 1280px 이상 너비

모든 크기에서 확인할 것:
- 탭 이름이 잘리는가?
- 파일 경로 입력칸과 버튼이 겹치는가?
- 진행 영역이 지나치게 작아지는가?
- 로그가 화면 밖으로 밀리는가?


13. 코드 작성 규정
================================================================================

13-1. 색상과 스타일
--------------------------------------------------------------------------------
새 UI 코드를 작성할 때는 먼저 기존 토큰을 사용한다.

권장:
- `UI_BG`
- `UI_SURFACE`
- `UI_SURFACE_HOVER`
- `UI_BORDER`
- `UI_BORDER_STRONG`
- `UI_CARD_BORDER`
- `UI_TEXT`
- `UI_TEXT_MUTED`
- `UI_ACCENT`
- `UI_ACCENT_HOVER`
- `UI_ACCENT_ACTIVE`
- `OVERLAY_BG`
- `OVERLAY_FG`

새 색상이 필요하면 먼저 이 문서를 갱신하고, 그 다음 `papastop.py` 상단 토큰에 추가한다.
함수 안에 새 hex 색상을 직접 넣지 않는다.

13-2. 공통 옵션 우선
--------------------------------------------------------------------------------
버튼, 입력칸, 선택창은 공통 옵션 딕셔너리를 먼저 사용한다.

예:
- 보조 버튼: `_ghost_btn`
- 위험 버튼: `_danger_btn`
- 입력칸: `_entry_kw`
- 선택창: `_option_kw`
- 주요 시작 버튼: `_primary_btn_kw`
- 중지 버튼: `_stop_btn_kw`
- 결과 열기 버튼: `_open_btn_kw`

공통 옵션으로 해결할 수 없을 때만 예외를 만든다.
예외를 만들면 왜 예외인지 코드 근처에서 짧게 알 수 있어야 한다.

13-3. 검증 순서
--------------------------------------------------------------------------------
UI를 바꾸면 아래 순서로 확인한다.

1. `python -m py_compile papastop.py`
2. `python -m unittest discover -s tests -v`
3. 앱 실행 후 기본 창에서 글자 겹침 확인
4. 파일 자막 탭에서 긴 경로 입력 시 버튼 밀림 확인
5. 실시간 자막 탭에서 미리보기 줄바꿈 확인
6. 화면 녹화 탭에서 시작/중지 버튼 상태 확인
7. 진행 상황과 작업 기록 영역에서 로그 스크롤 확인

화면을 직접 확인하지 못했다면 완료 보고에 "화면 직접 확인은 미검증"이라고 쓴다.


14. 작업 전 체크리스트
================================================================================

UI 작업 전후로 아래를 확인한다.

- 첫 탭이 `파일 자막`인가?
- 주요 시작 버튼이 화면에서 가장 먼저 보이는가?
- 중지 버튼은 빨간색이고 작업 중에만 활성화되는가?
- 보조 버튼이 시작 버튼보다 강하게 보이지 않는가?
- 입력칸 높이와 버튼 높이가 같은 줄에서 맞는가?
- 파일 목록과 로그가 자기 영역 안에서 스크롤되는가?
- 앱 전체 배경, 카드, 입력칸, 로그 색상이 서로 구분되는가?
- 새 색상값을 함수 안에 직접 추가하지 않았는가?
- 한글 글자가 잘리거나 깨지지 않는가?
- 최소 창 크기에서도 버튼과 글자가 겹치지 않는가?
- 실시간 자막 오버레이는 영상 위에서 읽기 쉬운가?
- py_compile과 unittest를 실행했거나, 실행하지 못한 이유를 남겼는가?


15. 최종 판단 기준
================================================================================
새 화면을 만들거나 기존 화면을 고칠 때 마지막으로 이 질문에 답한다.

"황재훈 님이 지금 무엇을 고르고, 무엇을 눌러야 하며, 작업이 어디까지 진행됐는지 바로 보이는가?"

답이 애매하면 장식을 줄이고, 색상을 줄이고, 입력칸과 버튼의 줄을 다시 맞춘다.
