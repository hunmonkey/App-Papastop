이 문서는 "기능 개선 / UI·UX 개선 / 오류 해결·성능 향상" 3가지 목표에 대한
실행 계획입니다. 실제 papastop.py 코드(3,516줄)를 읽고 함수명 기준으로 작성했습니다.
※ 아직 코드는 손대지 않았습니다. 이 계획에 합의한 뒤, 골라주신 항목만
   Rule_ToDo.txt의 "작업 진행 계획"으로 옮겨 [대기]→[진행]→[완료] 순으로 진행합니다.


------------------------------------------------------------
0. 현재 상태 요약 (분석 결과)
------------------------------------------------------------
- 단일 파일 tkinter 앱. 4개 탭: 시스템 사양 / 파일 자막 / 실시간 자막 / 화면 녹화.
- 음성→글자(STT): faster-whisper. ASREngine.transcribe()는 language=None(자동 감지),
  VAD 필터 ON, condition_on_previous_text=False, GPU에서 BatchedInferencePipeline 사용.
- 번역: TranslationEngine. NLLB-200(1.3B/3.3B, ctranslate2) 우선, 실패 시 Argos 폴백.
  목표 언어는 항상 한국어(kor_Hang) 고정 → 사용 목적(영/일/중→한)과 일치.
- 파일 자막: FileSubtitleWorkflow.run() → 추출→STT→번역→write_srt() 로 .srt 저장.
- 실시간 자막: LiveCaptionService. 청크(기본 5초) 단위로 캡처→STT→번역,
  _worker_loop()에서 미리보기만 emit. 떠 있는 자막창 LiveSubtitleOverlay 존재.
- 모델 1회 로딩, GPU 가속, EXE 번들은 이미 적용됨(메모리 로드맵 참조).

핵심 파일: papastop.py / tests(test_subtitle_utils.py, test_live_caption_service.py,
test_screen_recording.py) / build_package.ps1 / requirements.txt


------------------------------------------------------------
■ 목표 1. 기능 개선
------------------------------------------------------------

[F1] 실시간 자막을 파일(.srt)로도 저장   ★우선
  문제: 현재 실시간 모드(_worker_loop)는 미리보기만 보여주고 자막을 저장하지 않음.
        사용자 요청문 "저장하거나 실시간으로 출력"의 '저장' 절반이 비어 있음.
  개선: 청크별 자막에 누적 시간 오프셋을 더해 live-자막-날짜시간.srt로 이어 저장.
        (Rule_Todo_Done의 offset_subtitle_rows 아이디어 재활용 / 켜고 끌 수 있는 옵션)
  대상: LiveCaptionService._worker_loop(), 새 옵션 변수, write_srt() 재사용.
  난이도: 중 / 가치: 높음

[F2] 원본 언어 수동 지정(자동/영어/일본어/중국어)   ★우선
  문제: ASREngine.transcribe()가 language=None 자동 감지만 사용.
        특히 실시간 짧은 청크(5초)에서 언어 오판이 잦아 번역 품질이 흔들림.
  개선: 파일·실시간 탭에 "원본 언어" 콤보(자동/en/ja/zh) 추가 →
        transcribe()에 language 인자 전달. 자동이면 기존 동작 유지.
  대상: ASREngine.transcribe(), _build_ui()(콤보 추가), transcribe_kwargs.
  난이도: 하 / 가치: 높음

[F3] 자막 가독성 후처리(줄길이·병합·환각 제거)   ★우선
  문제: 세그먼트가 너무 길거나 짧고, 무음 구간 반복 환각 라인이 그대로 저장됨.
        (메모리 로드맵에도 "가독성 후처리 미구현"으로 명시됨)
  개선: write_srt() 직전에 post-process 함수 추가 —
        (1) 한 줄 글자수 제한 후 자동 줄바꿈, (2) 너무 짧은 인접 세그먼트 병합,
        (3) 동일 문구 연속 반복(환각) 제거.
  대상: 새 함수 + FileSubtitleWorkflow.run()/_worker_loop()에서 호출.
  난이도: 중 / 가치: 높음 / 단위 테스트로 검증 쉬움

[F4] 문장 단위 번역 재조합(문맥 보존)
  문제: 현재 세그먼트(자막 한 줄)별로 독립 번역 → 문장이 중간에 잘려 번역되면
        어색함. condition_on_previous_text=False라 STT 문맥도 약함.
  개선: 인접 세그먼트를 문장 경계(. ? ! 。 ？)로 합쳐 번역한 뒤, 길이 비율로
        타임코드를 다시 배분. 옵션으로 on/off(성능 영향 고려).
  대상: TranslationEngine.translate_texts() 호출부(워크플로우 쪽).
  난이도: 중상 / 가치: 중 (번역 자연스러움 개선)

[F5] 원문+번역 2줄(bilingual) 자막 옵션
  문제: 한국어만 출력. 외국어 학습·검수 시 원문 대조가 안 됨.
  개선: 체크박스 1개로 "원문 / 번역" 2줄 SRT 저장 선택.
  대상: write_srt() 또는 세그먼트 구성부, UI 체크박스.
  난이도: 하 / 가치: 중

■ 목표 2. UI / UX 개선
------------------------------------------------------------

[U1] 기본 탭 순서 재배치   ★우선(저위험·즉효)
  문제: 첫 탭이 "시스템 사양". 정작 자주 쓰는 자막/실시간 기능이 뒤에 있음.
  개선: "파일 자막"(또는 실시간)을 첫 탭으로, 시스템 사양은 맨 뒤로.
  대상: _build_ui()의 nb.add() 순서.
  난이도: 하 / 가치: 중

[U2] 실시간 미리보기·오버레이 가독성 강화
  문제: 미리보기가 마지막 2줄만(lines[-2:]) 작은 tk.Message로 표시.
        오버레이 LiveSubtitleOverlay는 폰트/배경/투명도 조절 불가.
  개선: (1) 스크롤 가능한 누적 미리보기 + 글자 크기 조절,
        (2) 오버레이 폰트 크기·배경 투명도 옵션 추가.
  대상: _build_ui()(live_tab), LiveSubtitleOverlay, _worker_loop emit 라인 수.
  난이도: 중 / 가치: 중

[U3] 파일 드래그&드롭으로 목록 추가
  문제: 파일 추가가 [선택]/[목록에 추가]/[폴더 추가] 버튼뿐.
  개선: 창에 파일을 끌어다 놓으면 목록(_append_to_queue)에 추가.
  주의(트레이드오프): 표준 tkinter는 DnD 미지원 → tkinterdnd2 의존성 추가 필요.
        EXE 용량/번들 영향 있음. 도입 여부는 결정 필요(아래 ■결정사항 참조).
  난이도: 중 / 가치: 중

[U4] 모델 다운로드·작업 진행률 가시화
  문제: 위스퍼/번역 모델 다운로드가 로그로만 흐름(진행률 없음).
        파일 배치 진행이 "전체 진행" 텍스트 위주.
  개선: 다운로드 단계 표시 보강, 배치에서 "현재 N/전체 M + 파일명" 명확화.
  대상: _prepare_asr_model(), _prepare_translation_model(), 진행 이벤트 처리.
  난이도: 중 / 가치: 중

[U5] 여백·폰트·톤 정리(가벼운 수준)
  문제: 현재 기본 ttk 위주로 위계가 약함(과거 카드 UI는 되돌려진 상태).
  개선: 폰트/여백/구분선 정도만 통일. 과한 리디자인은 지양(단순함 우선 원칙).
  대상: _configure_style()/_build_ui() 스타일 부분만.
  난이도: 하~중 / 가치: 중

■ 목표 3. 오류 해결 및 성능 향상
------------------------------------------------------------

[P1] 실시간 지연·청크 적체 대응   ★우선
  문제: 청크 1개 처리시간 > 청크 길이면 큐(maxsize=8)가 차서 밀림.
        사용자는 "왜 느려지지/끊기지"를 알 수 없음.
  개선: 청크 처리시간 측정·표시. 처리시간이 길면 경고 또는 청크 길이/모델
        하향 안내. _safe_put_chunk 드롭 동작 확인·로그.
  대상: LiveCaptionService._worker_loop(), _safe_put_chunk().
  난이도: 중 / 가치: 높음(실시간 체감 직결)

[P2] VRAM 동시 점유 관리(accurate 모드 OOM 방지)
  문제: ASR(GPU)와 NLLB-3.3B(GPU)를 동시에 올리면 VRAM 부족 가능.
        accurate 프로파일은 3.3B → 일부 GPU에서 메모리 부족 위험.
  개선: get_primary_cuda_vram_bytes()로 사전 점검 → 부족 시 1.3B 권장/자동 하향.
  대상: TranslationEngine._load_nllb(), build_resource_settings().
  난이도: 중 / 가치: 중

[P3] GPU 시작 실패 진단·안내 강화
  현황: max 모드는 GPU 실패 시 CPU로 몰래 전환 안 함(의도된 동작, _load_model).
  개선: 실패 메시지에 원인별 체크리스트(드라이버/ctranslate2/모델)와
        "균형 모드로 전환" 버튼/안내 연결.
  대상: _load_model() 예외 처리, friendly_error_message().
  난이도: 하 / 가치: 중

[P4] 종료·취소 시 자원 정리 점검
  문제: 스레드/ffmpeg 프로세스/임시 폴더(_temp_dir) 누수 가능성 점검 필요.
  개선: stop()/_cleanup()/TemporaryDirectory 경로의 예외·잔존 파일 확인.
  대상: LiveCaptionService.stop()/_cleanup(), ScreenRecorderService.stop().
  난이도: 중 / 가치: 중(안정성)

[P5] 테스트 보강
  개선: F3 후처리, F2 언어 지정, F1 라이브 SRT 누적에 단위 테스트 추가.
  대상: tests/test_subtitle_utils.py 등.
  난이도: 하 / 가치: 중(회귀 방지)

■ 권장 실행 순서 (단계별)
------------------------------------------------------------
원칙: "외과적·단순함 우선". 한 번에 한 주제, 각 단계 후 검증.

1단계 (저위험·즉효):  U1 탭 순서 → F2 원본 언어 지정 → F1 실시간 SRT 저장 → P1 지연 표시
2단계 (품질 향상):    F3 가독성 후처리 → U2 미리보기/오버레이 → P2 VRAM 관리 → P3 GPU 안내
3단계 (심화·선택):    F4 문장 재조합 → F5 2줄 자막 → U4 진행률 → U3 드래그앤드롭 → U5 톤 정리
상시:                 P4 자원 정리 점검 + P5 테스트 보강(각 기능과 함께)
